Falcon Onum Pipelines

What Is a Pipeline?

A Pipeline in Falcon Onum is an event-driven workflow that receives data through a Listener (Labels), processes it through a sequence of Actions, and routes the resulting event(s) to a Data Sink(s).

Pipelines are intended to:

  • •

    Ingest large volumes of data in real time

  • •

    Apply transformations, enrichments, or filtering

  • •

    Restructure and prepare event payloads

  • •

    Route events intelligently to downstream systems

The pipeline canvas is the visual environment where pipelines are designed, configured, and deployed. In the following modules, we'll reveal all its features and possibilities. But for now, let's take a look at its component sections:

  1. 1

    Node Palette: It contains the components you can add to your Pipeline. Components are divided into tabs:

    • Listeners (and its Labels)

    • Actions (organized by categories)

    • Data Sinks (Configured/Not Configured)

    Label (Listener)

  2. 2

Ports

Ports are used as connectors to other nodes (actions) of the Pipeline, linking either incoming or outgoing data.

Labels, which are associated with Listeners, function as the starting point for data flow in a Pipeline. Due to this role, they have a distinctive port configuration:

  • No input ports: Since Labels initiate the pipeline, they don't receive data from other components

  • One output port: Labels have a single output through which data exits

While Labels have only one output port, this single port can distribute its output to multiple downstream actions. In other words, the same output port can connect to several different action inputs simultaneously, allowing you to branch the data flow to multiple processing paths in the same Pipeline.

Actions are the processing components in a Pipeline with a specific port structure designed for reliable data handling:

  • Input Port: Actions typically have one input port that receives data from upstream components (Labels or other Actions)

  • Output Ports: Actions have two output ports that handle different scenarios:

    • Default Port: When an Action successfully processes data, the output is sent through this port to downstream components

    • Error Port: If the Action encounters problems while processing or sending data, the data is not discarded. Instead, it's automatically routed to the error port, allowing you to handle failures gracefully

This dual-port design ensures data integrity throughout your Pipeline. Even when issues occur, your data remains available for error handling, logging, or alternative processing paths rather than being lost. This makes Pipelines more robust and easier to troubleshoot.

A Datasink represents the final destination in a Pipeline where processed data is delivered and stored.

  • One input port: A Datasink has a single input port that receives the processed data from upstream components (Actions or Labels)

  • No output ports: Since a Datasink is the endpoint of the Pipeline, data does not flow out to other components

Datasinks mark the end of your Pipeline. Knowing they only accept input helps you identify the final processing step and ensures all data reaches its intended destination.

Conclusion

Pipelines in Falcon Onum combine three core elements to enable efficient, real-time data processing.

1. Pipeline Canvas: Your central visual design tool for creating workflows. The key components are:

  • Node Palette: Access available workflow components.

  • Canvas Area: Build and arrange your pipeline.

  • Top Bar Controls: Manage, save, and configure your work.

These intuitive design tools enable seamless data processing.

2. Metrics Bar: Displays data flow, processing rates, and latency in real-time. The key metrics tracked are:

  • Data throughput

  • Processing performance

  • Latency monitoring

This ensures optimal performance and identifies bottlenecks.

3. Ports & Dual-Port Design: Connect nodes and facilitate reliable data handling. The key capabilities are:

  • Managing errors through dual-port architecture

  • Maintaining workflow integrity during failures

This prevents data loss and keeps workflows running smoothly.

By mastering these three elements, you can design event-driven workflows that process data efficiently in real-time while maintaining reliability and performance visibility.
