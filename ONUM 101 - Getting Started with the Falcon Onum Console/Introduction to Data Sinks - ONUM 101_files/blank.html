Introduction to Data Sinks

Everything ends up in a Data Sink

Falcon Onum outputs data via Data Sinks. Use them to define where and how to forward the results of your processed and streamlined data.

Most aspects related to the visualization within the Data Sinks menu are the same as those previously mentioned for Listeners. This is intentionally designed to help end users become familiar with the console more quickly.

Data Sinks menu view is similar to the one for Listeners. This consistent design helps users navigate the console more quickly and interact with menus more intuitively. The key distinction is that data sinks manage outgoing data rather than incoming data

Data Sinks Integrations

You'll have noticed that creating a data sink is quick and quite simple. The most laborious part of the configuration takes place when the Data Sink is included within a specific pipeline for a particular use case. It is at this point that, for most Data Sinks, additional parameters regarding the destination and how the data will be sent must be specified. This parameterization will depend on the nature of the Data Sink itself.

As we mentioned for Listeners integrations, Falcon Onum is designed to be source-agnostic, ensuring you can send data from/to virtually any product or technology.

In the case of Data Sinks, and following the same philosophy, we rely on the same two pillars:

  • First, we offer a growing suite of dedicated Data Sinks for specific technologies. These provide a streamlined configuration process for popular services.

  • Second, and crucially, we provide standard protocol Data Sinks. This ensures that even if a product does not have a dedicated, named Data Sink, you can still seamlessly send data to your products using these widely supported, industry-standard protocols.

This dual model guarantees comprehensive coverage, making it clear that whether you need a highly specialized integration or simply a robust, standardized connection, Falcon Onum is ready to send your data.

Conclusion

This module focused on the concept of Data Sinks in Falcon Onum, emphasizing their role in managing processed data outputs and their integration within pipelines. Here are some key takeaways:

  • •

    Understand Data Sinks. They are essential for directing processed data outputs.

  • •

    Differentiate between dedicated and standard Data Sinks. Each serves unique integration needs.

  • •

    Utilize industry-standard protocols. They ensure compatibility across various products.

  • •

    Familiarize with the configuration process. It is key to effectively using Data Sinks in pipelines.
